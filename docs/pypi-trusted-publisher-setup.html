PyPI Trusted Publisher setup

One-time configuration so publish-python.yml can publish server-decorator to PyPI without storing a token.

tl;dr: PyPI lets you authorise a specific GitHub Actions workflow to publish on your behalf — no API token, no secret in GitHub. You add a “pending publisher” entry on PyPI before the project exists; the first successful publish from that workflow claims the project name.
1

Open the PyPI publishing page

Go to https://pypi.org/manage/account/publishing/ and sign in.

If you don't have a PyPI account yet, create one at pypi.org/account/register. Use the same email you'd use for any other open-source publishing.

2

Enable 2FA if you haven't already

PyPI requires two-factor authentication on any account that publishes packages or adds publishers. The publishing page will block you with a banner if 2FA isn't on.

If you see “Two-factor authentication is required”, follow the link in the banner — set up either an authenticator app (Authy / 1Password / Google Authenticator) or a hardware key. Takes ~2 minutes. Come back to the publishing page after.

3

Scroll to “Add a new pending publisher”

The publishing page has two sections. The top one (“Manage current trusted publishers”) lists existing entries — empty for you. Below it is the form you want.

"Workflow name" is just the filename, no path — PyPI knows it lives under .github/workflows/. "Environment name" is for repos that gate publishes through GitHub Environments; we don't, so leave it empty.

5

Click “Add”

PyPI registers the entry as a pending publisher. It will sit in the “Pending” list at the top of the page until the first publish run from that workflow claims the project name.

Name-squat risk: server-decorator is currently free on PyPI but anyone with an account can register it normally. Adding the pending publisher effectively reserves the name for your workflow. Don't delay this step.

After this

When you've completed step 5, tell Claude. Three things happen next:

  • CI on PR #1 finishes (Claude is monitoring it now).
  • Merge the PR to main.
  • git tag v2.0.0 && git push origin v2.0.0 — fires publish-node.yml and publish-python.yml in parallel. This step is irreversible (npm and PyPI don't allow deleting versions), so Claude will confirm with you before pushing the tag.
If the PyPI page now shows server-decorator in the Pending publishers list, you're done with this guide.
